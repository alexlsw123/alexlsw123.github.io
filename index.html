01

LH 홈닉 단지 전력 사용량 예측

기간2026.08 – 2026.11 소속헤리트 역할데이터 정제 · 모델링 · 평가 · 서빙 코드 · 인계 (1인) 기술TensorFlow 2.5 · scikit-learn HGB · pandas

문제

LH 홈닉 서비스 대상 77개 단지의 다음 날 24시간 전력 사용량을 시간 단위로 예측합니다. 하루 전 06시에 한 번 내고, 당일 02시에 전날 밤까지의 데이터로 다시 냅니다.

지켜야 했던 조건

  1. 학습 · 추론 · 관리가 모두 서비스 서버 안에서 끝나야 함 (Python 3.7 · TensorFlow 2.5 · CPU 8코어, GPU 없음)
  2. 계측이 자주 끊기는 부분수집 단지 47곳도 빠짐없이 예측
  3. 배포 기준: 전 단지 R² 평균 0.82 이상, 현행 모델보다 좋을 것

Chronos-2가 가장 정확했지만 Python 3.9 이상이 필요해 서버에 설치할 수 없었습니다. ONNX 변환은 런타임 도입 부담으로, 지식 증류는 교사 모델을 서버에서 돌릴 수 없어 접었고, Chronos-2는 남은 격차를 재는 기준으로만 썼습니다.

효과가 없던 모델 쪽 시도

  • 신경망 폭 32 · 48 · 96 · 128, 블록 수 변경
  • 입력 길이 28일 · 56일 (14일이 가장 좋음)
  • dropout, 배치 크기, 조기 종료 기준 변경
  • 시드 3개 → 6개 앙상블만 소폭 이득

여름에 기상을 넣으면 나빠졌던 이유

기상 이력이 겨울 몇 달뿐이라 모델이 난방기 관계(기온 1°C당 부하 −0.4%)를 배워 냉방기(+2.8%)에 거꾸로 적용했습니다. 계절별로 기상을 끄는 규칙을 결과를 보기 전에 정해 안 본 기간으로 검증해 쓰다가, 과거 예보를 채워 넣은 뒤 규칙을 없앴습니다.

Lost in Quantization

The Refusals a 4-bit Checkpoint Flips and Its Chat Template Hides

기간2026.10 – 2026.11 형태개인 연구 · AAAI-27 Workshop on Deployable AI 제출 · 1저자 기술vLLM · NVFP4 · ModelOpt · RTX 5060 Ti × 2

소비자 GPU 한 장에 8B 모델을 올리려면 보통 남이 4비트로 양자화한 체크포인트를 받아 씁니다. 받은 NVFP4 체크포인트가 원본과 같은 유해 요청을 거절하는지, 영어와 한국어에서 다른지, 그 차이를 얼마나 믿을 만하게 잴 수 있는지 물었습니다. 짝을 이룬 요청 2,014개, 8B 모델 3개, 블라인드 사람 라벨로 검증한 판정기 2개를 썼습니다.

  1. 채팅 템플릿이 양자화보다 크게 움직입니다. NVIDIA의 Llama-3.1-8B NVFP4 배포본에 딸린 템플릿을 BF16 원본에 쓰기만 해도 한국어 유해 요청 거절률이 34.6%에서 62.7%로 오릅니다.
  2. 순변화는 작아도 개별 응답은 뒤집힙니다. 순 거절률 변화는 5%p 미만이지만 유해 요청의 5~10%가 거절에서 응답으로 바뀝니다. BF16 재실행만으로는 0.5~2.2%입니다.
  3. 한국어가 더 흔들립니다. 영어 · 한국어 격차가 가장 큰 모델에서 한국어 거절이 3~9%p 더 자주 뒤집히고, 이중언어 보정으로도 줄지 않습니다.
  4. 평가 환경도 결과의 일부입니다. 같은 체크포인트를 GPU 2장에 나누기만 해도 한국어 유해 요청의 최대 9%가 뒤집힙니다.
